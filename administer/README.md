# 注册管理员板块

独立的教务员可视化工作台，复用项目现有的 MySQL `course_registration` 数据库和只读课程目录 API。默认监听 `127.0.0.1:8040`。

## 启动

先启动 MySQL Server，确认数据库表结构和演示数据已准备好，并安装项目依赖：

```powershell
py -3 -m pip install -r .\requirements-mysql.txt
```

在第一个 PowerShell 窗口启动课程目录 API：

```powershell
py -3 .\app.py
```

保持该窗口运行，在第二个 PowerShell 窗口启动注册管理员网页：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\administer\start.ps1
```

脚本会安全提示输入 MySQL 应用账号密码。打开 <http://127.0.0.1:8040>。

## 功能

- 只允许 `REGISTRAR` 角色登录和访问管理 API；所有写请求校验会话与 CSRF 令牌。
- 查看学生、教师档案，新增档案、修改身份信息与登录账户、停用账户。
- 新增档案时自动生成唯一编号，并同时创建对应的登录用户；初始密码在创建时设置。
- 新增和编辑教师时可勾选“授课资格”；教师列表的“授课资格（数量）”入口可打开维护表单。可跨院系配置，未勾选课程时会提示教师暂不能新增授课。资格与档案同事务保存，变更前后集合写入审计；旧客户端未传 `eligibleCourseIds` 的更新保留原资格。
- 撤销资格只禁止新增授课，不撤回已有有效班次；教师门户继续显示并允许保留原班次，撤回后须重新取得资格才能再选。目录已移除的旧资格显示为归档，可保留或移除。
- 社会安全号码可选录入。配置密钥后服务端以 AES-GCM 加密写入现有 `ssn_encrypted` 字段，列表和接口不会回传明文；编辑时留空保留旧值，可选勾选清除。
- 停用不物理删除数据库记录：账号不能登录，教师授课选择会撤回，课程、成绩、账单与审计关联保留。
- 原题“删除人员”在本版本采用逻辑删除：现有 `DELETE` 路由及“停用”按钮复用 `INACTIVE` 状态，并通过 `softDelete: true` 审计标识删除入口；编辑状态为停用则记录普通档案更新。两者都可恢复，均不代表物理删除或独立的已删除状态。详见 [需求约定](../docs/personnel-requirements.md) 和 [设计说明](../docs/personnel-design.md)。
- `OPEN` 表示注册尚未最终关闭，是否允许选课仍由注册、加退选日期窗口判断。最终关闭必须在两个窗口都结束后执行：截止日期当天仍可编辑，最早关闭日为 `max(注册截止日期, 加退选截止日期) + 1 天`。注册与加退选之间的空档也不能提前关闭，以保留后续加退选机会；所有窗口结束后可延迟结算，不设额外上限。已 `CLOSED` 的学期不能重复关闭。
- 教务员页面展示最早关闭日期、当前是否可结算及原因；跨日后可点击“刷新状态”。页面与写接口共用同一规则，写接口锁定注册期后重新检查，不信任客户端传入的权限标记。日期缺失或顺序错误时拒绝关闭；被拒绝的请求不会修改注册、课表、账单或审计。
- [关闭阶段的需求约定与接口说明](../docs/registration-close-policy.md)解释原题第 7 页“注册仍在进行”的日期含义及与加退选窗口的关系。
- 关闭时检查授课教师、人数和容量，按顺序尝试备选课，并核对先修课程与时间冲突；不满足最低人数（3 人）或未分配教师的开课会取消，仅将各课表中对应的注册记录标为取消，保留其他有效课程，并按保留课程生成账单。整张课表不会因此取消；没有有效课程的课表不生成账单。
- 补位前先移除无有效授课教师、已关闭或取消、或已从当前学期目录移除的开课，再按备选偏好顺序选择符合条件的课程；已注册且只是变为满员的有效课程仍保留。成功注册的主选和补位课程保持 `ENROLLED` 状态。
- 补位先修校验与学生提交共用 `database/academic_rules.py`：只认可 `COMPLETED` 注册记录且成绩为 `A/B/C/D` 的课程，`F`、`I` 和缺少成绩的记录不满足先修条件；重修任一次通过即可。
- 注册关闭成功后，按每学分 150 元的演示费率冻结金额（人民币分）、币种与最终课表快照，生成 `PENDING` 账单队列记录，支持幂等，关闭操作写入 `audit_logs`。

## 社会安全号码加密密钥（可选）

不录入这类号码时无需设置密钥。若需要录入，在启动服务的同一个 PowerShell 窗口生成一个随机密钥并保存在当前终端环境中：

```powershell
$env:SSN_ENCRYPTION_KEY = py -3 -c "import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
```

不要把密钥提交到仓库或发给协作人员。已有密文只能用生成该密文时相同的密钥解密；密钥遗失后不能恢复原号码。当前页面不提供解密或查看明文的入口。

## 会话权限

教务员会话在每次受保护请求前复查有效账号、`REGISTRAR` 角色、关联教务员档案及密码指纹；停用、角色变更或密码重置后旧会话被拒绝并移除。数据库复查失败返回 503。会话复查由各独立服务读取数据库完成，不依赖教务员进程能访问其他门户的内存会话；前端收到 401 后清除工作台数据并返回登录页。

## 账单队列

项目尚未提供外部账单系统地址。默认只写入数据库中的 `billing_transactions` 队列并保持 `PENDING`，不会伪标为已发送。若课程项目的账单接收端提供 HTTP JSON 接口，可在启动前配置：

```powershell
$env:BILLING_API_URL = 'http://账单服务地址/接收路径'
```

服务每 30 秒扫描 `PENDING/RETRY` 记录，发送 v1 JSON 与 `Idempotency-Key` 请求头。请求包含数据库中的总金额、`CNY` 币种、冻结费率、课程明细金额、学生与学期，以及最终课表的实际教师、院系、课程名称、时间与地点。只有 HTTP `200/201` 返回匹配交易号和幂等键的 `ACCEPTED` 确认后才标为 `SENT`；暂时故障重试，契约错误及永久拒绝标为 `FAILED`。

[完整接口契约、独立参考接收端与联调说明](../billing/README.md)包含启动命令、确认响应、重试与持久化幂等约定，以及旧版待发送快照的处理方式。参考接收端已经通过真实本地 HTTP 测试验证；项目尚未配置真实外部计费服务，默认入队不代表外部联调完成。

演示费率可用 `BILLING_AMOUNT_CENTS_PER_CREDIT` 覆盖，单位为“分/学分”，默认 15000（即每学分 ¥150）。费率改变只影响之后生成的账单，重试使用入队时冻结的金额和快照。

此模块面向课程设计演示。默认绑定本机，不含 HTTPS、集中式会话存储或生产部署防护。
