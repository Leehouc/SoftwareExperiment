# 人员与授课资格设计补充

对应需求：[人员维护与教师授课资格需求补充](personnel-requirements.md)。

## 数据与接口

复用 `professor_course_eligibility(professor_id, course_id)` 的联合主键及教师外键，不修改数据库表结构。课程编号来自外部只读目录，不能使用本地数据库外键关联外部课程。教师所属院系只表示人员归属，不自动授予该院系全部课程的资格。

- `GET /api/admin/data`：每个教师对象增加 `eligibleCourseIds`，包含该教师当前完整资格集合。
- `POST /api/admin/professors`：沿用教师档案字段，增加 `eligibleCourseIds` 字符串数组；省略时创建空资格，页面提示需补齐。
- `PUT /api/admin/professors/{id}`：提供 `eligibleCourseIds` 时替换完整集合，空数组表示清空；省略时保留原资格，以兼容旧客户端和仅修改档案的请求。
- 数组中的课程编号非空且不超过数据库字段长度 32；重复编号去重。新增编号须存在于当前目录，原有归档编号允许继续保留。非法输入返回 400，教师不存在返回 404。

上述写接口继承有效教务员会话与 CSRF 校验；教师不能通过教师门户自行授予资格。管理员端新增、编辑表单提供课程复选框，教师列表提供资格数量与跳转入口，归档编号单独标注。

## 事务与并发

新建时在同一事务中创建账户、教师档案、资格及审计。更新时先锁定教师档案，再读取并锁定原资格，校验新增编号，替换资格并记录审计。任何异常均回滚档案、账户、资格与审计。

教师保存授课选择同样先锁定教师档案，因此资格变更与教师保存不会交错使用过期资格。资格集合发生变化时记录 `UPDATE_PROFESSOR_ELIGIBILITY`，实体为教师，审计详情含 `before` 和 `after` 数组；重复提交相同集合不生成重复资格变更事件。档案创建和修改仍保留原有审计事件。

## 资格撤销与授课记录

资格表示新增授课的许可，授课安排表示已经登记的班次归属，两者分开维护。撤销资格不会自动删除或撤回有效授课安排，也不改写注册或成绩记录。

教师门户除合资格开课外，继续显示本人已有的 `SELECTED/CONFIRMED` 班次，并标记“资格已撤销，仅保留已有授课”。保存时允许保留这些班次；新增、接手或重新选择已撤回的班次仍需资格。名册及成绩权限继续依赖有效授课归属和学期规则。停用教师由原档案维护逻辑撤回有效班次，不使用资格撤销代替停用。

## 人员删除的存储语义

编辑档案设为 `INACTIVE` 是停用操作，审计为 `UPDATE_STUDENT_PROFILE` 或 `UPDATE_PROFESSOR_PROFILE`。现有 `DELETE` 路由采用逻辑删除，复用 `_deactivate_profile`：将档案改为 `INACTIVE`、账号 `is_active=0`，记录 `DEACTIVATE_*_PROFILE`，详情包含 `softDelete: true`。页面沿用“停用”文案，明确历史数据保留。

两种操作均不执行账户或档案的 SQL `DELETE`，不会级联清理学生课表、成绩、账单、资格及审计。教师有效授课选择标为 `WITHDRAWN`。每次请求的账号复查阻止旧会话继续使用；恢复为 `ACTIVE` 不恢复已撤回的班次。

此方案没有独立的 `deleted_at` 或 `DELETED` 状态。区分删除意图必须查阅审计，不能把 `INACTIVE` 直接解释为物理删除或不可恢复删除。如果后续要求隐藏已删除档案或禁止恢复，需要另行增加删除标记、迁移及恢复策略。
