# 人员维护与教师授课资格需求补充

本文件补充课程设计原题的人员新增、修改、删除要求，记录本项目采用的实现约定。原题 PDF 保持原样。

## 教师授课资格

- 教务员可以在新增教师时配置可讲授课程，也可以通过教师列表中的“授课资格”入口维护已有教师的资格。
- 资格以课程编号为单位，独立于教师所属院系，允许跨院系配置。新增资格必须来自只读课程目录，不能通过修改目录中的教师姓名代替资格配置。
- 教师档案、登录账号和初始资格必须一起成功或一起回滚。修改档案与资格也必须保持原子性；不得发生档案保存成功但资格配置失败的半完成状态。
- 可以暂不配置资格或清空资格，页面必须明确提示：无资格的教师不能新增授课班次。新建时选择了资格的教师登录后应能看到对应学期的开课，并遵守注册窗口、班次占用和时间冲突等规则。
- 撤销资格禁止新增相应课程的授课，保留已登记的有效班次、学生名册和成绩记录。教师可以保留或撤回原班次；撤回后需重新取得资格才能再次选择。停用教师仍按既有规则撤回有效授课安排。
- 已从目录移除的旧资格必须明确标为归档，允许保留或移除，不允许给其他教师新增不存在于目录中的资格。
- 资格维护仅允许有效教务员操作，写请求须校验会话及 CSRF，并记录操作者、教师编号和变更前后的资格集合。

## 原题“删除人员”的实现约定

| 操作 | 业务含义 | 本项目实现 |
| --- | --- | --- |
| 停用 | 暂停人员账户访问，可由教务员恢复 | 编辑档案，将状态改为 `INACTIVE`；账号设为不可用，记录 `UPDATE_*_PROFILE` |
| 逻辑删除 | 从可用人员中移除，同时保留关联历史 | `DELETE /api/admin/students/{id}` 或 `DELETE /api/admin/professors/{id}`；页面现有按钮标为“停用”，服务端记录 `DEACTIVATE_*_PROFILE` 和 `softDelete: true` |
| 物理删除 | 从数据库移除账户和档案行 | 不提供此操作，避免破坏课表、成绩、账单及审计关联 |

本版本用保留记录的逻辑删除承接原题删除要求，而不是宣称已实现物理删除。停用和逻辑删除共用 `INACTIVE` 状态；两者的操作意图区别通过请求方式及审计事件保留，不能仅凭状态字段判断。逻辑删除后的档案仍可在停用列表中查看，并可由教务员编辑恢复；本版本没有不可恢复的独立“已删除”状态。

停用或逻辑删除后，账号已有会话在下一次请求时失效；教师的有效授课选择撤回，已登记的学生课程、成绩、账单、授课资格和审计历史保留。恢复账户不会自动恢复已撤回的授课班次。

## 验收场景

1. 新建教师并勾选一门课程，登录教师门户能看到对应开课并正常选择。
2. 为已有教师增减资格，重新加载教师门户后生效；无资格课程无法新增授课。
3. 非法课程编号、无权限请求或保存失败，不改变原档案、账号或资格。
4. 撤销已有授课课程的资格后，原班次及名册仍可保留，撤回后不能重新选择。
5. 停用或逻辑删除人员后无法继续访问门户，历史数据不被物理删除，审计能区分操作入口。
